# 75-second demo script

Use the owner-private workspace. Open Outage replay and choose the real incident with the largest available event trail. If the current export has no matched replay, open the incident feed instead; do not record a fabricated ripple animation. Hide personal browser tabs and notifications.

**0:00–0:12 · Start the replay**

“I built Blast Radius around one sales signal: a company warning its customers about an upstream model provider. This replay shows when public reports appeared. It isn't proof of how failures propagated.”

**0:12–0:27 · Open a source**

“Each account starts with its own dated status report. Here's the exact evidence and the source. I keep the workaround context too, because an outage doesn't tell me whether they already have fallbacks.”

**0:27–0:43 · Account board, then drawer**

“The board prioritizes what we can actually observe. Enterprise fit, the current stack, and buying intent stay unknown until researched. The handoff gives the AE the evidence, relevant technical roles, and questions to qualify a current problem.”

**0:43–0:56 · Outreach tab**

“The draft opens on their incident and asks how they're handling that failure mode today. It doesn't tell an engineer that they lack failover, and it doesn't turn a resolved historical incident into a current emergency.”

**0:56–1:08 · Run ledger**

“The live augmentation runs through OpenRouter, with a different model for each task and a fallback array on each call. This ledger shows what actually ran and what it cost. I don't claim a fallback happened unless the response supports it.”

**1:08–1:18 · Public pulse, then methodology**

“The shareable version is a separate aggregate-only build. The named evidence stays private. Status aggregation already exists; the part I wanted to demonstrate is turning public evidence into an accurate sales conversation.”

Recording checklist: use actual ledger values, mention the measured collection coverage if asked, and call old examples historical. Do not say 20 qualified accounts, complete 90-day monitoring, universal failover, or a live alerting service unless the current evidence supports those claims.
